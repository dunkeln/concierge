# Persistent chats

- Each signed-in account owns its threads. Create a thread on its first message with an initial-request fallback title. After the first completed reply, make one separate title generation using `app/src/lib/server/stages/title.md`; save it in Neon. Bound generation to eight seconds without retries, and retain the fallback on failure. Title generation uses the existing chat model without tools and does not delay the first response byte.
- Store user messages before generation and assistant messages when their stream completes. Use immutable message IDs, a per-thread turn lease, and atomic completion so retries and concurrent tabs cannot overwrite history. Failed turns retain the user's message for retry. Consume the stream after a browser disconnect; a refreshed pending thread checks for completion.
- Restore transcript, selected place, date, slot, and explicit session cuisine when reopening a thread. Historical provider results retain their original timestamps and freshness rules. Signed browser tickets, browser frames, and reasoning are transient.
- The server loads conversation context from storage. The browser sends the newest user message and current selections. Keep the latest 19 messages in model context; older messages stay in the transcript and are loaded in pages of 100. No conversation summarization; the only additional model call is the initial title generation.
- The shared signed-in layout owns the collapsible chat sidebar, including the passport and preference pages. It lists the most recently updated threads in pages of 50. On mobile it overlays the page and closes with its toggle, backdrop, or Escape. Opening history never opens a browser preview.
- Account preference edits update the existing profile row. One-off chat choices remain thread-scoped. Passport entries and auth already have persistent storage.
- Use the existing Neon HTTP driver and Drizzle migrations. Index threads by owner/update time and messages by thread/position. Append two message rows per completed turn; avoid rewriting the full transcript or writing each token. Independent page/profile reads run in parallel.
- This migration adds chat tables to the existing auth/profile/passport database; it does not bootstrap a blank database. Existing unsaved browser conversations cannot be recovered from Neon.
